# BENCHMARK_SPEC.md — ARC-Style Structured Reasoning Benchmark

## 1. Task Families (minimum set, each its own generator module)

| ID | Family | Description |
|---|---|---|
| A | Boundary Propagation | fill/extend a bounded region given partial boundary markers |
| B | Motif Copying | replicate a small motif at specified locations |
| C | Translation | shift a shape by a vector, possibly wrapping |
| D | Reflection | mirror a shape across an axis |
| E | Rotation | rotate a shape by 90/180/270° |
| F | Color Transformation | remap colors per a demonstrated rule |
| G | Sequence Ordering | reorder tokens/cells per a demonstrated relation |
| H | Nesting / Containment | operate correctly across nested container structures, depth-parameterized |
| I | Pattern Completion | complete a partially-shown periodic/symmetric pattern |
| J | Multi-Step Transformation | compose 2+ of the above in one task instance |
| K | Demonstration-Conditioned Transformation | the transformation rule itself must be inferred from demonstrations (few-shot within the episode) |

Each generator exposes a common interface (`sample`) and a `difficulty` object controlling: grid size, number of colors, number of demonstrations, nesting depth, sequence length, noise level.

## 2. Splits

- **train**: used for gradient updates
- **validation**: used for model/hyperparameter selection and for fitting the Failure Risk Estimator (§ FAILURE_ANALYSIS.md) — never for reporting final numbers
- **held-out test**: fixed seed set, generated once, never touched until final evaluation
- **OOD test**: same families but with difficulty parameters outside the training range (e.g., grid sizes, nesting depths, or color counts never seen in train)

Splits generated by disjoint seed ranges per family; seed ranges recorded in `configs/experiments.yaml` and logged per run (REPRODUCIBILITY.md).

## 3. Difficulty Scaling

Each family defines an ordered difficulty axis (e.g., Nesting: depth 1..N; Sequence Ordering: length 1..N). The generator must support producing a **sweep** across this axis for the empirical threshold-discovery required by EXPERIMENT_PROTOCOL.md / FAILURE_ANALYSIS.md — not a fixed small/medium/hard bucket only.

## 4. Reproducibility Requirements

- All generation is a pure function of `(family, difficulty, seed)`.
- No task generator may access model state, predictions, or a "correct answer" cache from a prior run.
- Test/OOD split contents must never be logged in a way visible to training code paths (enforced by TESTING_SPEC.md's "evaluation does not access labels" test).

## 5. Metrics

| Metric | Definition |
|---|---|
| exact grid accuracy | prediction grid exactly equals target grid |
| cell accuracy | fraction of correctly predicted cells |
| task-level accuracy | fraction of task instances fully solved |
| transformation accuracy | correct *type* of transformation inferred, even if exact cells differ |
| semantic/structural accuracy | structural similarity metric (e.g., IoU of shapes) for partial credit |
| calibration | ECE (expected calibration error) between confidence and correctness |
| robustness | accuracy under input noise perturbation |
| OOD accuracy | accuracy on OOD split |

Reported per split: training / validation / held-out test / OOD (ARCHITECTURE.md §"Accuracy Target" — never fabricated, always sourced from `backend/eval/`).

## 6. Data Schema

See `schemas/task.schema.json` for the canonical `Task` object shape (input grids, demonstrations, target, metadata: family, difficulty, seed, split).
